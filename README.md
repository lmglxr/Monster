# Curious Beast 外部挂机 MVP

当前版本：`v0.0.2`

这是一个不修改游戏文件、不注入游戏进程的外部自动化原型。它组合使用：

- 游戏日志：识别普通场景、BOSS实体、BOSS血量和死亡；
- 屏幕 OCR：读取右下角悬浮提示中的疲劳值；
- 鼠标左键：地图寻路、入口绕圈、进入及退出副本；
- 键盘：连点 `A` 攻击，按住 `Space` 约一秒拾取。
- 进入副本：场景加载完成后自动按 `F` 骑乘宠物，再寻路前往 BOSS。

> 联网游戏可能禁止自动化工具。使用前请确认游戏规则，并自行承担账号风险。本工具不绕过反作弊、不修改疲劳/伤害/网络数据。

## 新电脑快速开始

仅支持 Windows 10/11。游戏本体需要通过 Steam 正常安装，本仓库不包含游戏文件。

1. 在 GitHub 页面点击 `Code` → `Download ZIP` 后解压，或者执行：

   ```powershell
   git clone https://github.com/lmglxr/Monster.git
   ```

2. 启动游戏并进入角色画面，保持窗口化运行。
3. 双击 `启动挂机MVP.bat`。第一次运行会自动创建独立环境并安装依赖，耗时可能为几分钟。
4. 第一次使用完整模式时，EasyOCR 会联网下载一次英文识别模型；之后可离线加载。
5. 按下 `F8` 开始，按 `F8` 暂停，按 `F12` 立即结束。

电脑没有 Python 时，首次启动会优先通过 Windows 自带的 `winget` 安装 Python 3.12。也可以先自行安装 Python 3.10～3.12，再双击 `一键安装.bat`。项目使用自己的 `.venv`，不会修改其他 Python 项目的包。

仓库可以克隆到任意目录，无须放进 Steam 游戏目录。默认的 `log_path: "auto"` 会根据正在运行的游戏进程自动找到 `Logs/Player.log`。

如果另一台电脑使用相同的 `1280×720` 客户区和相同 UI 缩放，仓库内的现有坐标通常可以直接使用。若分辨率、UI 缩放或按钮位置不同，先按下文执行一次校准。

## 当前基准

- 游戏窗口标题：`CreatureCurios`
- 录像和当前注册表配置：客户区 `1280×720`
- 普通场景：`1002`
- 冰牙海湾的场景实例 ID 每次进入都会变化，因此不将其写死
- BOSS实体：`100043`，初始生命 `18000`
- 低疲劳触发：`-800`
- BOSS循环目标：`800`
- 普通挂机疲劳轮询：默认每 `400` 秒一次
- 疲劳恢复：至少完成 `10` 次副本后才检查是否达到目标
- 死亡处理：识别中央复活面板，等待约 15 秒后自动选择“原地复活”

阈值和等待时间均可在 `config.json` 中调整。

骑乘功能可在 `config.json` 的 `dungeon_mount` 中单独关闭或调整按键、按住时间和稳定等待时间。它只使用快捷键，不依赖任何点击坐标。

装备切换与背包物品维护采用独立的个人坐标文件。仓库中提供 `inventory_profile.example.json` 作为模板；正式校准将写入不会提交到 GitHub 的 `inventory_profile.json`，不会污染地图、入口和 BOSS 坐标。

### 换武器与周期售药

- 第一次进入本轮 BOSS 恢复流程并到达 BOSS 点后，按 `B` 打开背包，自动定位两把主武器之一并双击，切到 BOSS 武器；后续副本保持该武器，不会每次重复切换。
- 疲劳恢复到 `800` 或更高后，先切回刷怪武器，再执行一次药品售卖，随后恢复普通挂机。
- 售卖流程为：打开背包 → 打开杂货铺 → 在背包网格内识别目标药品 → 持续按住并拖入回收格 → 自动识别并点击橙色确认按钮 → 验证数量弹窗消失 → 点击“全部出售” → 验证药品已从背包网格消失。
- 武器和药品不是按固定行列盲点。程序会在个人校准的背包网格内识别对应图标，因此售卖后物品自动重排也能继续定位。
- 背包、杂货铺、药品图标、武器图标或数量窗口任意一步识别失败，都会取消本次可选操作并继续挂机，不会误卖后暂停整个任务。
- 程序默认假设启动完整闭环时角色装备的是刷怪武器。若中途手动换过武器，先暂停脚本并恢复刷怪武器，再继续运行。

新电脑第一次启用这两项功能时，双击 `校准背包装备.bat`，根据提示记录背包网格边界、杂货铺按钮、回收格和“全部出售”按钮。数量确认按钮会按颜色与形状自动定位，无需记录固定位置。模板负责寻找格子里的物品，校准文件只负责限定各自界面区域。

校准后可以双击 `测试背包识别.bat` 做无损检查。它只会打开背包和杂货铺、报告武器与药品的识别分数，然后自动关闭界面；不会换装、拖拽物品或出售。当前没有目标药品时也可以通过测试，只会提示“未找到药品”。

## 第一次使用

如果默认坐标在新电脑上不准确：

1. 保持游戏窗口化运行，建议先使用 `1280×720` 客户区。
2. 双击 `校准坐标.bat`。
3. 根据控制台提示，在游戏里依次准备相应界面。
4. 每一步将鼠标放到指定按钮或地图点位中心，按 `F2` 记录。
5. 校准不会自动点击；按 `F12` 可以取消。
6. 双击 `测试疲劳识别.bat`，确认能读出类似 `101/1000`。
7. 若要使用自动换武器和售药，再双击 `校准背包装备.bat` 完成独立校准。

校准需要手动完成一次副本流程，以便记录普通地图入口、进入按钮、副本地图BOSS点、退出按钮和确认按钮。

如果只是地图无法展开，双击 `重新校准小地图.bat` 即可单独重录右上角圆形小地图中心，不必重新执行完整校准。自动流程每次都会先用模板确认地图确实打开；连续三次未打开会安全暂停，不会继续把地图目标坐标点击到普通地面上。

## 启动

校准并通过 OCR 测试后：

1. 双击 `启动挂机MVP.bat`，输入 `1` 运行完整闭环，输入 `2` 只刷副本。
2. 也可直接双击 `只刷副本.bat` 跳过选择。
3. 切回游戏窗口。
4. 按 `F8` 开始或暂停。
5. 按 `F12` 立即结束。

默认焦点脉冲模式允许游戏平时处于后台；真正发送输入时仍会短暂切到游戏窗口，然后恢复原窗口。旧版前台专用模式下，游戏失去前台会暂停操作。

### 焦点脉冲模式（v0.0.2）

默认启用 `window_control.input_mode: "focus_pulse"` 和 `capture_mode: "print_window"`：

- 游戏即使被浏览器、Codex 等窗口遮挡，也可以继续截图、OCR 和模板识别；
- 需要攻击、拾取、移动鼠标或点击按钮时，程序短暂将游戏切到前台；
- 输入完成后恢复此前使用的窗口和鼠标位置；
- 疲劳提示的“移出再移回”和 OCR 会合并在一次焦点会话中，识别结束后再恢复；
- 用户若在脉冲过程中主动切换到第三个窗口，程序不会强制切回旧窗口。

这不是完全无感的真后台输入。普通点击通常只占用焦点约 `0.1～0.2` 秒，疲劳 OCR 约 `1～2` 秒；战斗会按照攻击间隔频繁产生短焦点切换，因此同时打字可能出现焦点闪动或漏键。游戏不能最小化，Windows 也不能锁屏、休眠。

如果希望恢复旧版“游戏必须一直在前台”的稳定行为，将 `config.json` 中的 `window_control.input_mode` 改为 `foreground_only`，并将 `capture_mode` 改为 `screen`。

新电脑可以先让人物停在普通 HUD，然后双击 `测试焦点脉冲.bat`。测试会短暂打开并关闭地图、刷新疲劳提示、执行一次 OCR，并确认此前窗口和鼠标位置是否恢复；不会进入副本或持续攻击。

所有 `.bat` 入口都会自动检查 `.venv`。环境损坏或需要重新安装时，删除本地 `.venv` 文件夹后再次双击 `一键安装.bat` 即可；该目录不会上传到 GitHub。

普通挂机、普通地图寻路、副本内寻路和 BOSS 战都会统一监控死亡面板。检测到死亡后会立即释放 `A`、`Space`，暂停鼠标流程；“原地复活”由灰色变成橙色后才会点击。复活发生在寻路途中时，会重新打开地图并再次下发当前目的地；BOSS 战中复活则会重置本场战斗超时并继续攻击。

复活第一轮超时后，程序会重新截图、移开鼠标，并根据按钮检测区域中心重新定位“原地复活”按钮，再执行第二轮等待。第二轮仍失败才会安全暂停。

BOSS 战超过配置的最长时间后不会中断整个挂机任务。完整闭环模式会退出当前副本并立即重新检查疲劳：达到目标则返回普通挂机，未达到或本次 OCR 失败则继续下一次副本；只刷副本模式会退出当前副本后直接开始下一轮。超时退出不计入已完成副本次数。

同一时间只允许运行一个挂机脚本。进入地图寻路、入口操作和退出阶段时，程序会强制释放 `A`、`Space`，并默认等待 1 秒后再执行地图操作；静默时间可通过 `timing.combat_input_quiet_seconds` 调整。请同时关闭此前使用的连点器，否则外部连点器仍会独立发送按键。

“只刷副本”模式不会加载 OCR 模型，也不会检查疲劳。启动前请让人物位于普通地图、能够正常打开地图的位置；每次退出副本后都会重新打开地图并寻路到入口。

## 状态流程

```text
普通区域：A攻击 + Space拾取
  ├─ 任意阶段死亡：冻结输入 → 等待按钮可用 → 原地复活 → 重试当前步骤
  ↓ 默认每400秒读取一次疲劳
疲劳 <= -800
  ↓
打开地图 → 点击冰牙海湾入口 → 自动寻路
  ↓
识别传送圈 → 绕圈左键移动 → 出现副本面板
  ↓
进入副本 → 按F骑乘 → 打开地图 → 点击最远BOSS点 → 自动寻路
  ↓
本轮首次到达BOSS：打开背包 → 识别武器图标 → 双击切到BOSS武器
  ↓
按A并穿插Q/W/Space → 日志确认BOSS死亡
  └─ 日志没有死亡事件：连续两次确认疲劳明显恢复，判定BOSS死亡
  ↓
Space持续1秒 → 点击退出 → 点击确认
  ↓
至少完成10次后，OCR读取疲劳
  ├─ < 800：再次绕入口并进入副本
  └─ >= 800：切回刷怪武器 → 识别并出售目标药品 → 恢复普通区域挂机
```

## 诊断

- 完整链路冒烟测试参数：`smoke_test_config.json`。运行 `--full-smoke-test --live` 时会读取该文件中的快速阈值，参数只作用于当前测试进程，不会覆盖正式 `config.json`；每个参数旁均带有用途说明。
- 工具日志：`runtime.log`
- 游戏日志：默认自动从正在运行的游戏安装目录定位。只有自动定位失败时才需要修改 `config.json` 的 `log_path`。
- OCR失败截图：`debug/ocr_failed_*.png`
- 疲劳 OCR 会优先只读取提示框第一行，并通过红色通道增强数值；整块提示框识别仅作为兜底，日志中 `red:` 和 `focus:` 分别代表红字增强与第一行原图结果。
- 每次检查疲劳前，鼠标会先移到画面中央，再移回状态栏，以触发游戏重新生成提示框并显示最新数值；移出点和两段等待时间可通过 `fatigue.refresh_point`、`fatigue.refresh_leave_seconds`、`fatigue.hover_settle_seconds` 调整。
- 退出副本后的首次疲劳 OCR 完全失败时，默认再执行两轮“移出并移回”刷新识别；全部失败只记录警告并继续下一次副本，不会中断挂机。
- 红字精确区域默认使用客户区归一化坐标 `[0.895, 0.785, 0.998, 0.835]`；如果以后更改游戏 UI 缩放，可在 `fatigue.value_region` 中覆盖。
- OCR 失败图不是逐帧保存：默认至少间隔 60 秒，最多保留最新 20 张；两项均可在 `config.json` 的 `debug` 段调整。
- 如果入口模板识别失败，可以在 `config.json` 中降低 `portal_match_threshold`，但不建议低于 `0.42`。
- 如果自动寻路尚未完成就执行下一步，可增加 `normal_auto_path_seconds` 或 `boss_auto_path_seconds`。
- 单次游戏截图失败会重新获取窗口并最多尝试 5 次；窗口句柄失效时默认每 2 秒重新查找一次、最多 5 次，恢复后会读取最近的场景日志。
- 地图第一次无法展开时，默认执行两轮恢复：释放战斗按键、等待界面稳定、按 `ESC` 尝试关闭遮挡面板，再重新点击小地图。

## 死亡复活参数

死亡监控使用 OpenCV 小图模板和按钮颜色判断，不调用 OCR，默认每 `0.5` 秒检查一次。需要微调时，可在 `config.json` 顶层加入以下可选配置（不添加也会采用这些默认值）：

```json
"revive": {
  "check_interval_seconds": 0.5,
  "panel_match_threshold": 0.78,
  "ready_orange_ratio": 0.45,
  "max_wait_seconds": 45.0,
  "max_click_attempts": 3,
  "post_revive_seconds": 1.0
}
```

若脚本检测到死亡，但超过 `45` 秒仍无法成功原地复活，会安全暂停并写入 `runtime.log`，不会改点“返回营地”。
